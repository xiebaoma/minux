# 进程与调度

## 任务与就绪队列

`task_struct` 保存任务状态、队列节点、内核栈的首个页描述符、切换现场和入口参数。每个新线程有独立的 16 KiB 内核栈，首次切入时打开本地中断并调用 `entry(arg)`。入口返回后，调度器先切走，再由接手的任务回收旧任务的栈和描述符。

单 hart 共用一条 FIFO 就绪队列。`schedule()` 取队首任务，将仍可运行的当前任务放到队尾。阻塞任务留在等待队列，退出任务交给下一任务回收。启动任务进入 idle 循环后，负责在就绪队列空时执行 `wfi`，并在有任务后恢复调度。

## 时钟抢占

定时器每秒触发 10 次。中断处理先重新设置下一次截止时间并累计 tick，再在返回 trap 前调用 `schedule()`。此时 `pt_regs` 保存在被抢占线程的内核栈上。`arch_switch_to()` 保存 C 调用约定要求保留的寄存器并切换栈。旧线程重新被选中后，从原来的调度调用返回，经汇编恢复 `pt_regs` 并执行 `sret`，继续原来被中断的指令流。

调度器关闭本地中断后操作就绪队列，切回时恢复该任务原有的中断状态。Buddy 和 slab 的自旋锁在持锁期间关闭本地中断，因此时钟抢占会推迟到释放锁后。持锁期间禁止主动调度或进入等待队列。

## 等待队列

`wait_event()` 在关本地中断的同一区间内检查条件、入队和切走，避免在检查条件与入睡之间丢失唤醒。生产者更新条件后调用 `wake_up_all()`，等待者按入队顺序回到就绪队列。线程被重新调度后再次检查条件，条件仍不满足就继续睡眠。

这些接口沿用 Linux 的 `task_struct`、切换现场、就绪队列和等待队列概念。Minux 当前使用单 hart、单 FIFO 队列和每 tick 轮转，等待时通过回调检查条件。SMP 调度见路线图。

## v0.6 用户态调度

`task_create_user()` 接管调用者准备好的独立 `mm`，并为用户入口和栈指针建立初始现场。用户任务、内核线程和 idle 任务共用调度路径。调度器关本地中断后按任务的 `mm` 选择页表，内核线程和 idle 使用启动根表。RISC-V 后端在切换根表时写入 `satp` 并用 `sfence.vma` 刷新地址翻译。所有根表共享高半区内核映射，因此内核栈在切换页表时仍可访问。用户任务销毁时一并释放其地址空间。

## v0.6 退出与等待

用户任务创建时会取得独立的正整数 PID。由用户任务创建的进程加入其子进程链表，链表和就绪队列在同一个关本地中断区间内更新。

`exit` 或无法处理的用户态异常会记录退出状态并切走任务。接手的任务释放原任务的内核栈和地址空间，再将它标为 `TASK_ZOMBIE` 并唤醒父进程。父进程通过 `wait4` 取出 PID 和状态并回收描述符。父进程先退出时，已退出的子进程立即回收，仍在运行或等待的子进程脱离父子关系，退出时由内核自动回收。内核线程继续在入口返回后自动回收。

`wait4` 复用等待队列，关中断检查是否有匹配的已退出子进程，并在需要时阻塞。当前支持指定正整数 PID 或用 `-1` 等待任意子进程，选项支持阻塞等待和 `WNOHANG`，`rusage` 需传 `NULL`。子进程回收后写回四字节状态，写回失败时返回 `-EFAULT`。

## v0.6 派生进程

RV64 通过 `clone(SIGCHLD, 0, 0, 0, 0)` 提供 fork 语义。当前支持继承用户栈和独立地址空间，其他标志或非零子栈指针返回 `-EINVAL`。每个子进程有独立的内核栈，架构层在栈上复制父进程的用户寄存器现场。父子从同一条 `ecall` 的下一条指令继续，父进程取得子 PID，子进程取得 0。内核栈或地址空间分配失败时返回 `-ENOMEM`，新进程只在构造成功后取得 PID 并加入就绪队列。

## 验证

`make test` 在开启真实定时器中断后启动两个忙等线程。两个线程都必须在没有主动调度的情况下观察到对方恢复执行，然后正常退出并归还内核栈。启动自测覆盖 FIFO 轮转、全部等待者阻塞时回到 idle、提前唤醒后重新睡眠，以及条件满足后按序恢复。原有 UART/PLIC 回归继续验证串口回显、后续 tick 和 QEMU 正常退出。

用户态自测让两个任务访问同一个虚拟地址，并检查各自读写的私有数据。任务在忙等时把 `sp` 设为未映射地址，靠时钟抢占完成两轮交互。测试随后验证切回时恢复内核页表和寄存器，以及销毁任务后归还地址空间和内核栈。

退出与等待自测通过真实用户态系统调用验证父进程先等待和子进程先退出两种顺序。用例检查阻塞唤醒、正常和异常退出状态、`WNOHANG`、无匹配子进程、坏状态指针、孤儿进程和资源回收。

普通启动与自测启动使用同一个 `/init`。调用 `clone(SIGCHLD, ...)` 前，数据页中的 `child_argv[1]` 为 `NULL`。子进程向这个槽写入指向字符串 `"42"` 的指针，触发 COW。随后 `execve` 从子进程的私有页复制参数，`/disk/bin/child` 从新栈读取并校验参数，按磁盘上的程序版本以 42 或 73 退出。父进程用 `wait4` 核对子 PID 和编码后的退出状态，再检查自己的参数槽仍为 `NULL`。校验通过后，`/init` 用 `execve` 在同一 PID 下启动 `/bin/sh`。shell 等待前台子进程退出后再次显示提示符，在空提示符处收到 EOF 时以 0 退出。

`make test` 按启动日志中的实际 PID 检查父子执行与退出顺序，再验证串口回显、时钟中断和 QEMU 关机。独立的内存自测检查写入前的物理页共享、写后的私有副本及回收后的空闲页数。[写时复制与 ELF 加载](MM.md)
