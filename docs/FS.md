# 文件系统

## 启动和挂载

`rootfs_init()` 将内嵌的 newc 归档展开成 ramfs 目录树，注册控制台设备。探测到启动盘时，它读取 ext2 根 inode，并将它接到 ramfs 的 `/disk`。路径查找经过这个挂载点后使用 ext2 的目录操作，`/disk/..` 返回 ramfs 根。`/init` 在进入 shell 前需要执行 `/disk/bin/child` 并回收其退出状态。`make run` 默认挂载构建生成的 `build/disk.ext2`。[根文件系统初始化](../init/rootfs.c) · [用户态启动过程](../user/init.S)

| 路径 | 来源和用途 |
|---|---|
| `/init` | initramfs 中的 ELF，由内核启动 |
| `/tmp` | 可写 ramfs，保存本次启动创建的文件 |
| `/dev/console` | 串口 TTY，连接初始进程的标准输入、输出和错误 |
| `/disk/bin/child` | 只读 ext2 中的 ELF，由子进程调用 `execve` 执行 |

## VFS、文件描述符与管道

与 Linux 的打开文件语义一致，Minux 将文件身份、打开位置和进程内编号分别放在三处。挂载持有 `struct inode`，每次打开得到一个记录访问模式和偏移的 `struct file`，进程的 fd 表按编号保存指向它的引用。系统调用通过 `uaccess` 传递用户缓冲区，ELF 加载器则通过 `vfs_read_at` 按段的文件偏移直接读入内核缓冲区。[VFS 接口](../include/minux/fs.h) · [fd 表实现](../fs/fdtable.c)

每进程有 16 个 fd 槽，`openat` 分配最低可用编号。支持普通文件的 `O_RDONLY`、`O_WRONLY`、`O_RDWR`、`O_CREAT`、`O_EXCL` 和可写打开时的 `O_TRUNC`。绝对路径忽略 `dirfd`，相对路径仅支持 `AT_FDCWD`，当前工作目录固定为 `/`。创建时接受 `mode` 参数，权限检查留待后续版本。

普通文件的 `read` 和 `write` 按实际传输量推进偏移。独立打开各有自己的位置，fork 继承的 fd 共享位置，exec 保留 fd，close 和进程退出释放引用。归档文件首次写入时复制到可写内存，重启后恢复归档内容。

内核在首次调度 `/init` 之前打开 `/dev/console`，将 fd 0 设为只读，将 fd 1 和 fd 2 设为只写。启动日志中的 `minux: hello through pipe` 是子进程写入匿名管道、父进程从管道读回后通过 `write(1, …)` 输出的内容。

`dup3(oldfd, newfd, 0)` 将目标槽替换为源打开文件的引用，两个 fd 共享访问模式和偏移。替换时释放目标槽的旧引用，因此覆盖管道的最后一个写端也会触发 EOF。Minux 当前支持 flags 为 0，源和目标必须不同。

`pipe2(fds, 0)` 返回读端和写端。每条管道有 4096 字节的环形缓冲区，读空、写满时通过等待队列睡眠。最多 4096 字节的单次写入会等待足够空间。最后一个写端关闭后，读端先读完剩余数据，再返回 0。最后一个读端关闭后，写入返回 `-EPIPE`。当前仅支持阻塞模式。

shell 为前台管道启动两个子进程。左侧接管道写端作为标准输出，右侧接读端作为标准输入，各自关闭多余的 fd，再从左到右应用本命令的文件重定向。父进程关闭自己的管道两端，回收两个子进程后才显示提示符。

## 串口按行输入

UART 接收中断把字节交给 TTY。普通字符立即回显，退格（BS 或 DEL）擦除当前行的最后一个字节。回车或 LF 提交一行，唤醒等待输入的读者。`read(0, …)` 每次最多返回一行并保留换行符。缓冲区较小时，剩余部分留给下一次读取。

Ctrl-D 提交当前行，读者只收到此前输入的字节。空行首的 Ctrl-D 使一次非零长度读取返回 0，因此无参数的 `cat` 会退出。TTY 的 256 字节环形队列由已提交的行和正在编辑的行共用。空队列最多接受 255 个普通字节，留一个位置给换行或 Ctrl-D。超过容量的输入字符会被忽略。[TTY 实现](../fs/console.c)

## 从 ext2 文件偏移到扇区

路径查找从根 inode 2 开始。每一级目录通过目录项取得下一级 inode 号，根据块组描述符找到对应的 inode 表。普通文件的前 12 个逻辑块直接从 inode 取块号，后续块号从一级间接块读取。驱动把一次跨块请求拆开，读满调用者请求的字节数或到达文件尾。普通文件中块号为零的区域读作零。默认 1 KiB 块的镜像可寻址 12 + 256 个数据块，单文件上限为 268 KiB。双重、三重间接块、符号链接和磁盘写入均在 v0.7 范围之外。[只读 ext2 实现](../fs/ext2.c)

通用层提供直接读 `blk_read` 和缓存读 `blk_read_cached`，参数为起始扇区、扇区数和内核缓冲区。每台设备有 8 个直接映射的扇区缓存槽。整个范围在发出 I/O 前检查。零长度读可从盘尾开始，后端在多扇区读取中途出错时，前面成功读取的数据可能已复制。容量和镜像内容在挂载期间应保持固定。

RISC-V 平台从设备树收集启用的 virtio-mmio 窗口，驱动选取第一块现代 MMIO v2 块设备。队列 0 同时处理一个读请求，轮询完成后才将数据交给调用者。若设备超时，驱动停用该队列并保留 DMA 缓冲区。

`make test` 会分别报告 `block (memory)` 和 `block (virtio-mmio)`。测试盘在 ext2 卷尾之外附加 32 个已知扇区，与内存模拟盘共用容量、内容和越界检查，内存设备另外记录后端读取次数并模拟 I/O 失败，以验证缓存命中、替换和重试。

文件系统只向 `struct block_device` 请求扇区。QEMU 平台发现、MMIO 地址映射和 DMA 地址转换留在平台层，virtio 请求队列由驱动管理。移植到其他架构时，新块设备后端实现相同的扇区接口即可复用 ext2 读取逻辑。[块设备接口](../include/minux/block.h) · [RISC-V 平台探测](../arch/riscv/virt.c)

## 测试镜像与验收

宿主机使用 `mke2fs`、`debugfs` 和 `e2fsck` 生成并校验 2 MiB 镜像，固定块大小、inode 数量和大小、UUID、时间戳及文件系统特性。测试文件 `/disk/share/probe/pattern` 长 17 KiB 加 37 字节，内核自测按已知字节模式校验跨直接块和一级间接块的读取，并检查短读、EOF、只读错误和损坏目录项。[镜像生成脚本](../tools/mkext2.py) · [ext2 自测](../tests/test_ext2.c)

`make test` 用同一个自测内核分别启动两张盘。每次均核对磁盘子进程的 PID、执行路径和父进程回收的状态。更换磁盘后父进程观察到的退出码由 42 变为 73。串口测试还覆盖前台命令、`cat` 的行编辑和 Ctrl-D、管道两端的退出、重定向截断和读回，以及出错后重新显示提示符。[串口验收脚本](../tests/test_uart_irq.py)
