# Minux 路线图

## 目标

1. 在 RISC-V 64 上实现一个结构完整的宏内核，包括进程、虚拟内存、VFS、设备驱动和系统调用。
2. 子系统划分与核心抽象和 Linux 保持对应，使每个模块都能与 Linux 的实现直接比较。
3. 沿用 Linux RISC-V 系统调用 ABI，从零实现 Minux 的用户态 libc 和命令行环境。将来可用 musl 静态程序和 BusyBox 检验 ABI 兼容性。

## 当前范围之外

- 完整的 POSIX 或 Linux 兼容性：只实现运行目标用户程序所需的子集
- QEMU `virt` 以外的硬件平台
- 动态链接、图形界面

## 设计原则

- **架构隔离**：硬件相关代码限定在 `arch/riscv/`，通用子系统不直接依赖具体架构。
- **接口对齐 Linux**：数据结构、函数命名和系统调用编号尽量与 Linux 一致，偏离时在设计文档中说明原因。
- **先正确，后优化**：每个子系统先给出最简可用的实现，接口稳定后再逐步替换为更完善的算法。
- **可调试性**：在功能之前优先建设日志、断言、栈回溯和启动自检。

## v0.8 开发步骤

沿用 v0.7 的 RV64IMAC、LP64 软浮点交叉工具链、静态 ELF 和 initramfs。用户程序链接项目自己的代码。每步新增对应测试，并用 `make test` 回归两张 ext2 镜像。

| 步骤 | 实现范围 | 验收 |
|---|---|---|
| 1. 第一个 C 程序 | 自写用户态启动入口 `_start`，从已有初始栈取出参数和环境，调用 `main`，将返回值交给 `_exit`。最小 libc 先提供 `write` 和 `_exit`，复用已有内核系统调用。 | 汇编 `/init` 派生子进程执行 `/bin/hello`。C 程序读到指定参数和环境变量，输出一行；父进程回收到约定退出码。 |
| 2. 两个基础命令 | 自写 `/bin/echo` 和 `/bin/cat`。按需给 libc 增加 `read`、`open`、`close` 和字符串函数。 | 由测试程序分别执行两个命令，核对多参数输出和文件内容，验证 `cat` 在文件末尾退出。 |
| 3. 串口按行输入 | UART 驱动把收到的字节交给通用 TTY 层，后者负责缓冲、回显、退格和按行唤醒。为 `/init` 接好标准输入、输出和错误。 | 在 QEMU 串口输入并退格修正一行，用户程序通过 `read(0, …)` 读到修正后的内容；空行首按 Ctrl-D 可读到 EOF。 |
| 4. 第一个 shell | 自写 `/bin/sh`，用定长缓冲区读命令，按空白拆分参数，通过已有的 fork、exec、wait 接口执行前台程序。首版接受绝对路径。 | 在串口输入 `/bin/echo hello` 得到 `hello` 并返回提示符；输入不存在的命令后还能继续执行下一条。 |
| 5. 管道与重定向 | 为文件描述符补上复制到指定编号的操作，复用已有的管道、文件打开和关闭逻辑，让 shell 支持一条管道以及 `<`、`>`。 | 执行 `/bin/echo hello \| /bin/cat > /tmp/out`，再执行 `/bin/cat < /tmp/out`，得到 `hello`。两个子进程均被回收，shell 返回提示符。 |

**架构边界。** 用户侧的启动汇编、`ecall` 和寄存器约定集中在 libc 的 RISC-V 子目录。通用 libc、命令和 shell 使用 C 接口；用户程序通过系统调用访问内核。

**后续按需扩展。** 当程序需要动态内存时，再一起设计匿名 `mmap` 和 libc 的 `malloc/free`；需要 Ctrl-C 中断前台命令时，再引入信号与可中断等待。两项各自都有独立的使用场景和测试。

## v1.0 之后的方向

- SMP 多核支持（每 CPU 运行队列、核间中断）
- procfs、sysfs
- 网络：virtio-net 与 TCP/IP 协议栈
- 页缓存、页面回收与 swap
- 可加载内核模块
