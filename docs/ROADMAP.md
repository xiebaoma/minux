# Minux 路线图

本文记录 v1.0 已完成的里程碑。下一轮开发见 [v2.0 开发路线图](ROADMAP-v2.md)。

## 目标

1. 在 RISC-V 64 上实现一个结构完整的宏内核，包括进程、虚拟内存、VFS、设备驱动和系统调用。
2. 子系统划分与核心抽象和 Linux 保持对应，使每个模块都能与 Linux 的实现直接比较。
3. 沿用 Linux RISC-V 系统调用 ABI，从零实现 Minux 的用户态 libc 和命令行环境。将来可用 musl 静态程序和 BusyBox 检验 ABI 兼容性。

## v1.0 范围之外

- 完整的 POSIX 或 Linux 兼容性：只实现运行目标用户程序所需的子集
- QEMU `virt` 以外的硬件平台
- 动态链接、图形界面

## 设计原则

- **架构隔离**：硬件相关代码限定在 `arch/riscv/`，通用子系统不直接依赖具体架构。
- **接口对齐 Linux**：数据结构、函数命名和系统调用编号尽量与 Linux 一致，偏离时在设计文档中说明原因。
- **先正确，后优化**：每个子系统先给出最简可用的实现，接口稳定后再逐步替换为更完善的算法。
- **可调试性**：在功能之前优先建设日志、断言、栈回溯和启动自检。

## 里程碑

带版本标签的里程碑可在仓库的 Tags 页面查看。

| 版本 | 里程碑 | 范围 | 完成标准 | 状态 |
|---|---|---|---|---|
| v0.0 | 引导 | 交叉构建系统、链接脚本、入口汇编、SBI 调用封装 | 从 OpenSBI 进入 `start_kernel`，输出启动信息并正常关机 | ✅ 完成 |
| v0.1 | 内核基础设施 | `printk`/`panic`、`lib/string`、`list_head`、FDT 解析 | 启动时输出 hart 信息与物理内存布局 | ✅ 完成 |
| v0.2 | 异常与中断 | trap 入口与上下文保存、未处理异常诊断、定时器与外部中断分发、PLIC、UART 中断驱动 | 周期性时钟中断；串口输入经中断回显 | ✅ 完成 |
| v0.3 | 物理内存管理 | 页帧分配器（buddy）、`kmalloc`（slab 简化实现） | 分配器启动自检通过，内存统计准确 | ✅ 完成 |
| v0.4 | 虚拟内存 | Sv39 页表、高地址内核映射、`mm_struct`/`vm_area_struct` | 启用分页后内核正常运行；非法访问被捕获并报告 | ✅ 完成 |
| v0.5 | 进程与调度 | `task_struct`、上下文切换、内核线程、抢占式调度、自旋锁、等待队列 | 多个内核线程在时钟驱动下抢占运行 | ✅ 完成 |
| v0.6 | 用户态与系统调用 | 系统调用入口（Linux ABI）、ELF 加载、`fork`（COW）/`execve`/`wait4`/`exit`、缺页处理 | `/init` 派生子进程，验证写时复制、执行第二个 ELF 并回收退出状态 | ✅ 完成 |
| v0.7 | [文件系统](FS.md) | VFS、initramfs、文件描述符、管道、virtio-blk、块缓存、ext2、设备文件 | 同一内核从两张 ext2 镜像执行程序，分别回收到 42 和 73 | ✅ 完成 |
| v0.8 | 用户环境 | 自研最小 libc、串口 TTY、基础命令和 shell | 在 Minux 自己的 shell 中运行外部命令，验证管道和文件重定向 | ✅ 完成 |
| v1.0 | 稳定版本 | 全量回归、正式镜像启动验证、构建和使用文档 | 两张测试盘各通过 537 项内核检查及串口集成测试，正式镜像可交互运行 | ✅ 完成 |

**架构边界。** 用户侧的启动汇编、`ecall` 和寄存器约定集中在 libc 的 RISC-V 子目录。通用 libc、命令和 shell 使用 C 接口；用户程序通过系统调用访问内核。

**后续按需扩展。** 当程序需要动态内存时，再一起设计匿名 `mmap` 和 libc 的 `malloc/free`；需要 Ctrl-C 中断前台命令时，再引入信号与可中断等待。两项各自都有独立的使用场景和测试。

## v1.0 之后的方向

- SMP 多核支持（每 CPU 运行队列、核间中断）
- procfs、sysfs
- 网络：virtio-net 与 TCP/IP 协议栈
- 页缓存、页面回收与 swap
- 可加载内核模块

各子系统的设计文档放在 `docs/` 下，内容包括数据结构、关键流程、与 Linux 实现的对照，以及取舍说明。
